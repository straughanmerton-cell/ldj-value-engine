## 1. 系统要回答的问题

1. 这款茶到底是什么身份？
2. 哪些市场产品和它在同一条价值赛道？
3. 这条赛道当前公开价格能走到多高？
4. 高价产品为什么贵？
5. 这款产品已经具备哪些高价值基因？
6. 有强对标时，怎样把“同赛道、高标准”讲到极致？
7. 没有强对标时，怎样自己建立一套高端产品标准？
8. 怎样让主播讲得有身份、有结构、有价格感、有记忆点？
9. 怎样保证话术“够狠”，但不虚构可核验事实？

## 2. 两套语言

| 层 | 目标 | 允许 | 禁止 |
|---|---|---|---|
| 研究层 | 事实、证据、价格、对标、相似度、高价原因、风险 | 克制、保守、标注 unknown | 无证据推断 |
| 成交层 | 身份、气势、画面、价值、价格锚定、产品结构、购买理由 | 极强修辞、排比、反问、身份塑造 | 新增事实、承诺收益 |

## 3. 必须避免的产品误区

```text
竞品很贵 ≠ 龙德记未来一定很贵
无真实研发关系 ≠ “我们就是按某经典配方做的”
```

正确路径：

```text
市场高价值产品 → 拆解价值结构 → 龙德记具备哪些底层条件 → 讲成极强价值叙事
```

## 4. 两种成交模式

### 4.1 Benchmark Mode（高价值对标模式）

触发：`Similarity >= 70 AND PriceEvidence >= 75`，且选定主锚点。
叙事：市场已证明这条赛道存在很高的价值上限；研究经典成功原因，再看本产品已握有哪些底层价值基因。

### 4.2 Category Creator Mode（自建高端标准模式）

触发：没有足够可靠的高价值锚点，或用户选择不使用对标。
硬要求：**文案不得变弱**；改为自建产品标准、产品结构、配方哲学、风格身份证、价值逻辑与王者话术。
禁止：硬凑竞品、降低阈值到不合理、编造对标。

## 5. 产品结构（Product Architecture）

字段：`backbone`、`identity`、`aroma_role`、`body_role`、`front_stage_role`、`middle_stage_role`、`finish_role`、`memory_point`、`value_role`。
约束：不得新增任何原料或配方事实。

## 6. 配方哲学（Formula Philosophy）

字段：`formula_strategy`、`backbone_component`、`aroma_component`、`sweetness_component`、`body_component`、`finish_component`、`design_goal`、`known_ratio`、`ratio_data`。
约束：`known_ratio = false` 时禁止出现任何比例（schema 层已强制校验）。

## 7. “牛逼化”按钮

```text
普通 → Level 2
强势 → Level 3
爆款 → Level 4（默认）
王者 → Level 5
```

点击“再狠一点”：提升气势、身份、画面、价值、记忆点、金句密度，**不增加新事实**，重新评分，最多 3 轮，每轮保存版本。

## 8. 强度与评分门槛

```text
Level 4  冲击力 >= 85
Level 5  冲击力 >= 90
<70 自动重写 / 70–79 可用 / 80–89 优秀 / 90+ 核心主播稿
```

Level 5 每次必须包含：1 个强反问、1 个身份定义、1 个价格高度叙事（有证据时）、1 个产品结构叙事、1 个风格身份证、≥3 句短视频金句、1 个成交收口。

## 9. 事实与修辞

| Claim Type | 含义 | 例 |
|---|---|---|
| FACT | 可核验事实，必须有证据 | 布朗山大树春料 |
| INTERPRETATION | 基于事实与品饮表现的解释 | 布朗山提供浓强骨架 |
| RHETORIC | 修辞 | 烟香就是它的身份证 |

审核关键：**是否会让消费者误认为存在一个并不存在的可核验事实。**
RED 禁止审批发布。
